    Parse a JUnit XML report and return normalized test results.

    Test identities follow the shared pytest contract path::name, the same format links --build writes. The path comes from the testcase file attribute when present, otherwise from the dotted classname (tests.test_ranker -> tests/test_ranker.py).

    		 required

    Returns:

    Raises:

    Type Description

    rank_tests(stats, changed_files, links)

    Rank tests using a simple baseline score. Inputs: stats: Historical statistics produced by db.get_test_stats() changed_files: List of source files changed in the pull request. links: Mapping of source files to related tests. Current baseline scoring: +10 if test is linked to changed code +5 for each historical failure Then divide by average runtime. This favors tests that are: - relevant to the current change - historically failure-prone - relatively inexpensive to run This is the initial baseline ranker, not the final TestBudget research ranking algorithm.

    rank_tests_coverage(stats, changed_files, links, file_weights)

    Rank tests by greedy budgeted maximum coverage of the changed files.

    Each test covers the changed files linked to it. A file is worth 1 + file_weights.get(file, 0). The test with the largest uncovered value per second (duration floored at 0.1 s) is picked next, then the files it covers keep 0.3 of their remaining value. Tests that cover no changed file go last, most recent failure first (last_failure, an ISO timestamp, if the stats carry it), then by name. Ties break by name. Args: stats: Historical statistics, as db.get_test_stats returns. changed_files: Source files changed in the pull request. links: Mapping of source file to linked test names. file_weights: Failure weight per file, e.g. from riskmap.file_failure_weights. Returns: Ranked tests in the shape rank_tests returns; score is the value per second at the moment the test was picked.

    testbudget.selector

    Budget cut over a ranked, rule-ordered test list.

    select_with_budget(ranked_tests, budget)

    Select ranked tests while staying within the supplied time budget.

    Forced tests (forced=True, set by the hard rules) are always selected and their duration counts against the budget first, even past it. The remaining tests are considered in ranking order; a test that does not fit is skipped, and later shorter tests may still be selected. Args: ranked_tests: Ranked tests with duration and optional forced. budget: Time budget in seconds. Returns: {"selected", "skipped", "estimated_runtime", "budget"}; selected tests keep ranking order, skipped tests carry skip_reason. Raises: ValueError: If budget is negative.

    select_with_rules(ranked_tests, budget, context)

    Apply the hard rules, then cut the result to the budget.

    Pinned, rotation-limit and full-suite tests are forced: they count against the budget but are never cut.

    Parameters:

    Name Type Description Default
    ranked_tests Iterable[Mapping[str, Any]]

    Output of ranker.rank_tests.

    		 required
    budget float

    Time budget in seconds.

    		 required
    context RuleContext

    		 required

    Returns: select_with_budget output plus run_all and trigger from rules.apply_rules. Raises: ValueError: If budget is negative or the rule inputs are malformed.
